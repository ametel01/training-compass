# Command contract

These names are stable handoff interfaces. Supporting scripts may change without changing what each command proves.

| Command | Contract |
| --- | --- |
| `make bootstrap` | Validates stable Xcode 26+, Swift 6, and resolves the pinned package graph. It does not obtain credentials, sign, install, or touch owner data. |
| `make verify` | Runs formatting, dependency boundaries, privacy checks, deterministic fixtures, the package build and tests, the optimized iOS Simulator build, and diff hygiene. |
| `make verify-performance` | Validates the deterministic 15-year Verification Data Envelope and the privacy-safe Release-build repeated-run protocol, including P95, HealthKit wait separation, resource/energy pause conditions, storage budgets, and waiver fields. |
| `make verify-evidence` | Validates the optional ignored release evidence index when present. It checks the closed schema, sanitized dependency graph, and absence of sensitive fields; a missing index is reported as not yet recorded rather than treated as a release pass. |
| `make verify-final-release` | Runs every automated gate, requires passing Acceptance Device records for all six owner-usable milestones, regenerates the current evidence index, and accepts only a revision-matched Milestone 6 `eligible` release verdict. |
| `make acceptance` | Verifies that the version-controlled acceptance matrix covers every delivered issue source and all five required scenario classes, including unified identity, enrichment, and route contracts, and that the release-candidate budget checklist retains the resolved numeric envelope. |
| `make test-ui` | Runs the critical launch/navigation journey on an available iOS Simulator. |
| `make fixtures` | Regenerates seed 21571 in memory and fails if the checked-in synthetic manifest differs. `UPDATE_FIXTURES=1 make fixtures` updates it for deliberate review. |
| `make verify-migrations` | Creates every historical authoritative (v1–v16) and reconstructible (v1–v10) schema prefix, upgrades each directly to current, compares deterministic fingerprints, exercises interruption/retry, validates the v1 export path, and writes privacy-safe `fixtures/migration-compatibility.json` evidence. |
| `make device-smoke MILESTONE=gate-0|health-foundation|unified-events|training-insights|recovery-evidence|personal-team-refresh|healthkit-write-back` | Prints the selected attended physical-device checklist. With explicit result metadata and milestone-specific booleans, writes a privacy-safe ignored record; passing release measurements must include one conditioning run, ten Release-build runs, P95, the Verification Data Envelope seed, and separate HealthKit wait/app-controlled timing. The Write-back record separately captures opt-in, recovery, version/correction, deletion/restoration, ownership, and Full App Erasure checks without measurements. |
| `make verify-release MILESTONE=gate-0|health-foundation|unified-events|training-insights|recovery-evidence|personal-team-refresh|healthkit-write-back` | Repeats change and UI gates, then refuses success unless the selected milestone's physical-device evidence passes. Release milestones also require validated release-envelope measurements; Personal Team evidence records profile dates instead because this is an attended signing/install continuity check; Write-back evidence requires the dedicated deletion/restoration/erasure checks. Unified route evidence may explicitly be unavailable when the Acceptance Device has no route-bearing workout. Training and Running Insights evidence additionally proves every displayed derived value reaches an explanation and that insight queries meet the 750-millisecond budget; Recovery Evidence additionally proves available and withheld guidance, explanation reachability, current-day correctness, neutral language, resource limits, privacy, and prior-data continuity; Personal Team evidence proves stable identity, preflight, profile inspection, in-place install, launch smoke, data continuity, and privacy. |
| `make evidence` | Writes an ignored, inspectable JSON index containing command revisions, sanitized dependencies, capabilities, entitlements, privacy artifacts, fixture and algorithm versions, compatibility results, coarse environment metadata, raw privacy-safe measurements, waivers, all milestone device evidence, and explicit gate verdicts. Automated gates use `pass`, `fail`, or `not_run`; device evidence uses `pass`, `fail`, or `missing`; each milestone gate is `eligible` or `blocked`. CI records `pass` only after an automated gate succeeds, and only attended device evidence can prove OS file attributes. |
| `make install-iphone` | Friendly attended cable-install entry point. It selects the newest complete Xcode installation (or `TRAINING_COMPASS_DEVELOPER_DIR`/`DEVELOPER_DIR` override), discovers exactly one paired, unlocked wired iPhone, the Training Compass bundle on that device, and one local Apple Development team from Xcode's account cache, signing identities, or profiles; it never asks the owner to type a Team ID when Xcode has one unambiguous free Personal or Individual development team. A fresh install needs no recovery export. Before updating an existing installation, it selects the newest local `.trainingcompass` export from Downloads, Desktop, Documents, or iCloud Drive and requires fresh verification confirmation. The app destination is always the stable bundle ID on the selected iPhone, not a user-selected Files path. When the login keychain has no usable development identity, it asks Xcode automatic signing to create or refresh one for that device and prints periodic progress during first-time package resolution and compilation. It tolerates Xcode 27's delayed keychain-identity visibility only after verifying the exact code signature, embedded team, and bundle identifier. Device build caches live under the user's normal Xcode DerivedData directory rather than the repository. It then delegates profile inspection, installation, launch smoke testing, and applicable data continuity to `make personal-team-refresh`; it never uninstalls, persists a device identifier, uses distribution signing, or requests credentials. `TEAM_ID=...` and `EXPORT_PATH=...` remain optional ambiguity overrides. |
| `make personal-team-refresh` | Runs the attended Personal Team maintenance workflow. It requires a logged-in macOS session, explicit free Personal Team and Apple-session confirmation, the stable team/device/export environment, and explicit device/data confirmation; it builds with automatic signing, inspects the embedded development profile, installs over the existing app, launch-smoke-tests, and records a privacy-safe result. It never uninstalls or stores credentials. |
| `make install-personal-team-refresh-reminder` | Installs a per-user Aqua LaunchAgent that runs the refresh preflight/reminder once per day around the Personal Team day-five window. It does not build, sign, install, uninstall, or handle credentials. |

No command stores Apple credentials. Device installation, profile renewal, and launch confirmation remain attended operations. The Personal Team workflow also requires a verified Training Compass Export before it can install over the existing app.
